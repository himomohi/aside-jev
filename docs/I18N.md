# Localization

English (`en`) is the default. Korean (`ko`) is an explicit alternative. User-authored goals, candidates, observations, and payloads are not translated when the interface language changes.

| Surface | Default | Korean selection | Source |
| --- | --- | --- | --- |
| Dashboard | English on a fresh visit | Header language selector; saved locally | `src/aside_jev/static/i18n.mjs` |
| Extension popup | English with no saved preference | Popup language selector; saved locally | `extension/i18n.mjs` |
| Extension-manager metadata | English fallback | Browser's own locale | `extension/_locales/{en,ko}/messages.json` |
| CLI help and doctor | English | `aside-jev --lang ko doctor` or `aside-jev doctor --lang ko` | `src/aside_jev/cli_i18n.py` |
| Repository README | `README.md` | Top-level Korean link | `README.ko.md`, `README.i18n.json` |
| Video/GIF/poster | Unqualified filenames are English | `.ko` media; `--locale ko` | `video/src/locales/{en,ko}.json` |
| Supporting docs | Unqualified filenames are English | `.ko.md` sibling | Paired Markdown files |

## Interface behavior

- A fresh dashboard or popup uses English even if the browser language is Korean.
- A saved choice applies only to that surface. It does not change the OS, browser, or Aside account language.
- Changing language updates labels, accessible names, placeholders, status, and built-in examples while preserving user-edited task inputs.
- Unknown/stored unsupported locales fall back to English. Storage being unavailable must not stop the UI from working.
- Manifest metadata follows Chrome's localization mechanism; it may differ from the explicitly chosen popup language.
- Product names, units, candidate IDs, machine-readable JSON keys, error codes, and API payloads remain stable.

Backend/provider diagnostic text and generated agent instructions retain their original language. The UI translates known error codes and marks original diagnostic details separately. CLI localization covers help, doctor output, and CLI-owned validation messages; protocol diagnostics are not a translated API contract. Third-party parser/system text can also retain its original language.

The dashboard ships inside the Python package while the unpacked extension must be self-contained. Their UI dictionaries are distributed in both locations; a parity check prevents the copies from drifting.

## Documentation and video

GitHub Markdown has no runtime language picker. Each README offers a link to its translated sibling. [`README.i18n.json`](../README.i18n.json) records the language-to-artifact mapping; localized READMEs link their matching video, GIF, poster, and product screenshot.

Both video languages use the same composition, benchmark JSON, and time scale. Only the text dictionary changes. See [render instructions](../video/README.md). The speed comparison remains a localhost SDK transport experiment, excluding model inference, in both languages.

## Updating translations

1. Add or update English strings, then their Korean keys. Keep placeholders identical.
2. Update both README/doc variants when facts, commands, or boundaries change.
3. Rerender both video locales after changing on-screen text. Refresh screenshots from the actual localized UI.
4. Validate parity, language behavior, links, and render output:

```bash
uv run pytest -q
node --test tests/test_*i18n.mjs tests/test_extension_controller.mjs
uv run python scripts/check_i18n.py
cd video
bun run check
bun run render --locale all
bun run gif --locale all
```

Changes to translation text do not authorize edits to user input, model decisions, or stored account configuration.
